# Tracking package file names: plan

Status: **accepted 2026-10-30: D1 = C (unpack, then rename), D2 = fold the speed modules in.** Names approved 2026-11-01. Release 1a (renames inside the engine) applied and passed 2026-11-02: the A1 replay matched speed177 byte for byte in both steps. Release 1b (engines ship as folders) applied 2026-11-02.

Scope: the files that ship in the public `pymicroglia.tracking` package. Run folder names, intermediate files and saved settings keys are out of scope (2026-10-30, Jamie).

## Where the odd names are today (2026-10-30 inventory)

| Where | Example | Count | Why it reads oddly |
|---|---|---|---|
| `tracking/*.py`, one flat folder | `disk_owner_batch.py`, `hierarchy_partial_hoist.py`, `convex_hull_image_fast.py` | 232 modules | 121 are named after how a speed pass made a step faster (`_boxes` 28, `_reuse` 28, `_batch` 12, `_memo` 8, `_index` 8 ...), not after the step they belong to |
| Inside `tracking/data/motion_engine.zip` (ships in the wheel) | `accepted_history_ops/issue006/s1_detect_contacts.py` | 37 files | named after the bug report or recording well that prompted the correction |
| Same zip | `boundary_owner_excursion.py` + `boundary_owner_excursion_integration.py` | 58 pairs | every step split into a body and an `_integration` wrapper |
| Engine function names | `_issue005`, `_well_b3_issue005_component_continuity_duplicate_takeover` | 102 | same bug-report origin |

The speed modules exist because the engine is a frozen zip: each one swaps a faster, exact version of one engine function in by name when tracking starts (`install()` + `setattr`). Once the engine is ordinary package code, the faster version can simply be the function, and the speed module disappears.

## Target shape

```
tracking/
  run.py            public entry (today engine.py)
  stages/           one module per stage, named for what it does, in run order
  corrections/      accepted-history corrections, grouped by what they repair:
    ownership/  seats/  merges/  gaps/  processes/  presence/  lineage/
  safety/           stage_fallbacks, pipeline_fallbacks, checkpoints, retries
  evidence/         audits, provenance, correction records
```

Every file and function is named for what it does. Bare `_issueNNN` functions need such a name; a read-only pass proposes them and Jamie approves the table.

## Decisions

**D1. How the engine's files become normal package files.**

| Option | What changes | Cost and risk |
|---|---|---|
| B. Rename inside the frozen zips | Zip contents renamed; the 121 speed modules stay, re-targeted to the new names | New engine fingerprint; the flat folder and speed-pass names remain |
| C. Unpack the engines into `tracking/`, then rename | Zips removed; engine and PyMicroglia modules merge into the target shape | Largest; one replay-validated release; ends the zip-and-patch layering |

Recommendation: **C.** Only C removes the speed-pass file names, because they exist only to patch a zip.
If wrong: C touches every tracking file. A half-done move leaves two layouts, so the move lands as one release that must pass the full A1 replay (identical labels) and the test suite.

**D2. What happens to the patching modules under C** (195, of which 121 have speed-pass names).

| Option | Result |
|---|---|
| Fold each into the function it speeds up | The fast version becomes the function; the file is deleted. Its exactness test moves beside the step |
| Keep them as a `speed/` sub-package | Fewer edits, but the odd names stay public |

Recommendation: **fold in.** Keeping a separate faster copy next to the original is the layering C exists to remove.
If wrong: folding loses the side-by-side original that the exactness tests compare against, so each test must keep a frozen copy of the original function as its reference.
